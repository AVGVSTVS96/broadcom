# BROADCOM

The dashboard for a CLIProxyAPI account pool: which account takes new work, how much each plan and API credit has left, how fast it's going, who spent it, and adding or removing accounts. Next.js 16 (Cache Components, React Compiler), shadcn on Base UI, Tailwind 4, Effect 4.

The pool spends cheapest first: plans, then free credit, then paid extra usage. Free credit costs nothing: API keys holding the monthly API credit a Max or Ultra plan includes, in an organization with no card, so they need no extra-usage switch. Paid extra usage bills money, and only on an account whose owner turned extra usage on. Call each by those names; "API credit" alone doesn't say which.

## Layers

- `lib/proxy/`: the only code that talks to the proxy. `schema.ts` holds the Effect Schemas for every payload; `proxy.ts` is the `Proxy` service (management key read on the server, never sent to a browser). A new proxy API is a new Layer here, nothing else changes.
- `lib/live/`: the live stream. The server decodes the proxy's SSE (`event.ts`) and re-sends typed events from `/api/live`; `client.tsx` keeps them in one store per tab. `useLive(select)` must return a value already in the store (`live => live.accounts`); derive from it in the component.
- `lib/model/`: pure functions that turn proxy data into what a page shows (pace, run-out, windows, totals). Tested with `bun test`.
- `features/<page>/`: a page's components. `app/` routes stay thin: read data on the server, derive with `lib/model`, and pass client components only what they draw (a live chart gets its points; a 10 MB payload never leaves the server).
- `components/ui/`: generated by `bunx shadcn add`; `components/viz/`: shared chart pieces (meters, hatching, axes, legends), SVG with d3-scale/d3-shape for the math.

## Look

Bloomberg terminal × Vercel × Linear, Swiss Helvetica, drawn heavily from the inspiration board (`~/Developer/pages/pages/broadcom-inspiration/`, mostly Headroom by @Niyxuis): a chart should visibly come from one of those images, in this app's style.

- A section is a `Section` card (`components/viz/section.tsx`). Its title is the verdict, a sentence with the number in it ("Max 20x is 1.5× ahead of even pace"), and the line under it is the evidence. View toggles sit top right.
- Numbers are big, light and tabular, with the unit small and muted beside them (`Stat`). Meters are thick rounded bars (`Meter`) or tick rows (`Ticks`).
- Color means state, never decoration: greys for data, `ok` green for room, `over` amber for ahead of pace, `bad` coral for run out, hatched coral (`HatchPattern`) for locked until reset, dashed for forecast. `brand` orange marks only the account taking new work.
- Accounts are told apart by name and position, in greys, with the one in focus in full ink. Legends sit in one muted line under the chart.
- Phone first: one column at 390 px, names above full-width tracks, nothing scrolls sideways except a chart that says so.

## Rules

- `bun run check` passes before every commit; lefthook runs it. Fix the code, keep `oxlint.config.ts`.
- Effect 4 is newer than model memory: read the `.d.ts` in `node_modules/effect/dist/` (`Schema`, `effect/http`, `Stream`, `effect/encoding` `Sse`).
- Every string goes through the clean-copy ladder (`~/Developer/pages/tools/newsprint/clean-copy.md`): delete before rewording.
- Light and dark follow the system. Check 390 px and 1440 px wide, both themes, before calling a page done.
- Signed Conventional Commits, straight to `main`. The repo is public: no names, emails, keys or tailnet addresses in code, fixtures or screenshots.
